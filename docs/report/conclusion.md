# Вывод: рекомендуемый стек для публикации результатов исследований

Для публикации результатов исследований в предметной области веб-технологий и машинного обучения на стороне клиента рекомендуется использовать стек **MkDocs + Material + Git + Helios**.

В качестве генератора статического сайта предлагается **MkDocs** с темой **Material**. Такой вариант подходит для публикации результатов экспериментов, описания методики исследования, исходного кода, таблиц, графиков и технической документации. MkDocs использует Markdown, поэтому материалы исследования можно хранить непосредственно в репозитории вместе с исходным кодом.

**Git** используется для хранения исходного кода, материалов исследования и истории изменений. Для фиксации отдельных версий результатов могут использоваться Git tags и releases. Это позволяет связать опубликованный материал с конкретной версией исходного кода.

В качестве хостинга рекомендуется использовать **Helios ИТМО**. Для статического сайта он не требует серверного приложения и позволяет размещать готовые HTML-, CSS- и JavaScript-файлы. Развертывание можно автоматизировать через GitHub Actions с использованием SSH и `rsync`. Дополнительно можно реализовать healthcheck, preview-версии для отдельных веток и резервное копирование предыдущей версии.

Итоговый стек:

```text
Markdown
   ↓
MkDocs + Material
   ↓
Git
   ↓
GitHub Actions
   ↓
SSH + rsync
   ↓
Helios
```

Такой стек является достаточным для исследовательских материалов, в которых основной результат представлен в виде веб-страниц, описаний экспериментов, исходного кода, графиков и статических демонстраций.

## Ограничения рекомендации

Рекомендация может измениться при изменении характера исследовательского результата.

**1. Необходимость большого количества научных вычислений.**

Если публикация должна содержать большое количество воспроизводимых вычислений, интерактивных ноутбуков, математических формул и автоматически генерируемых отчетов, целесообразно рассмотреть **Quarto** или связку Jupyter + Quarto. В таком случае научная составляющая публикации становится важнее документирования веб-проекта.

**2. Необходимость сложной научной документации.**

Если основной результат представляет собой крупную техническую документацию с большим количеством API-описаний, перекрестных ссылок и сложной структурой, может быть выбран **Sphinx**.

**3. Необходимость встроенной поддержки научных публикационных метаданных.**

Если требуется активно использовать библиографические метаданные, ORCID, DOI, форматы цитирования и автоматическое формирование научных документов, преимуществом может обладать Quarto. При этом DOI все равно предоставляется внешней системой архивирования, а не самим генератором.

**4. Требование к серверной части.**

Если исследовательский результат требует базы данных, серверного API, авторизации или выполнения моделей на сервере, одного статического хостинга Helios будет недостаточно. В таком случае потребуется серверная инфраструктура или другой тип хостинга.

**5. Необходимость запуска машинного обучения непосредственно на сайте.**

Для исследований клиентского машинного обучения может потребоваться выполнение моделей непосредственно в браузере. В этом случае статический сайт остается подходящим для публикации, но дополнительно потребуются JavaScript/WebAssembly/WebGPU и сами модели. Если же модели должны выполняться на сервере, потребуется серверная инфраструктура.

**6. Необходимость долговременного архивирования.**

Helios подходит для размещения доступной веб-версии исследования, но сам по себе не заменяет архив публикаций. Для долговременной фиксации конкретной версии результата целесообразно использовать Git tags/releases и внешний архив с постоянным идентификатором, например DOI.

## Итог

Для текущей предметной области оптимальным является простой статический стек:

```text
MkDocs + Material
        +
Git
        +
GitHub Actions
        +
Helios
```

Он позволяет одновременно хранить исходные материалы исследования, формировать понятный веб-сайт и автоматически публиковать его на сервере ИТМО.

При этом рекомендация не является универсальной: **для веб-ориентированных результатов и технических исследований подходит MkDocs + Material, а при смещении в сторону воспроизводимых вычислений, научных публикаций и сложных библиографических материалов целесообразно рассмотреть Quarto; при необходимости серверной логики потребуется дополнительная серверная инфраструктура.**
